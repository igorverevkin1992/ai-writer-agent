# 0.1. Конституция канона
## Документ уровня 0 — всегда в контексте. Версия 1.0

## 1. Иерархия источников (при противоречии выше бьёт ниже)

1. **Прямое указание автора в текущей сессии** (фиксируется в журнале 3.6, если меняет канон)
2. **Журнал канонических решений (3.6)** — последняя запись сильнее ранней
3. **Живые реестры (уровень 3):** эпистемическая матрица, закладки, континуити, выбытия, снапшоты
4. **Канон тома (уровень 2):** реестры информационного режима, арки, поглавники
5. **Канон мира (уровень 1):** хронология фабулы, досье, организации, предметы, хроники
6. **Регламенты (уровень 0)** — правила формы; по содержанию уступают 1–5, по форме не уступают никому
7. Черновики прозы

## 2. Процедура при обнаружении противоречия

СТОП → зафиксировать оба источника дословно → предъявить автору вариантами с последствиями каждого → решение автора → запись в 3.6 → правка проигравшего источника. **Запрещено: молча выбрать версию, молча сгладить, продолжить генерацию «поверх».**

## 3. Процедура нового факта (принцип П6)

Факт, рождённый в прозе (дата, адрес, шрам, привычка, имя, предмет), в той же сессии вносится в профильный реестр: физика → 3.3; знание → 3.1; предмет → 1.5+3.3; смерть/исчезновение → 3.4; событие фабулы → 1.2 (с Ф-ID). Несённый факт = несуществующий: при следующей генерации он не защищён.

## 4. Правило статусов хроник

Исторические факты имеют статус ✓ (проверено) или ⚠ (требует проверки). Инструмент строит сцены только на ✓. Попадание ⚠-факта в сцену = флаг автору, не тихое использование. Канонизированные условности (🔧) используются свободно, но не детализируются сверх записанного без решения автора.

## 5. Разделение режимов

**Генерация** и **верификация** — разные проходы, в идеале разные сессии. Генератор не проверяет сам себя; верификатор работает по чек-листам 4.1–4.3 и не переписывает прозу — только флагует. Правки — третьим проходом.

## 6. Информационная дисциплина

Генератор главы обязан иметь в контексте: 0.1–0.4 целиком; строки матрицы 3.1 всех участников сцены; реестр 2.2 своего тома (окно ±3 главы); карточки 1.3 участников; снапшот предыдущего тома. Генератор НЕ должен тянуть в сцену знания из будущих томов (закладки кладутся по реестру 3.2, а не по памяти о финале) и подробности, которых нет в канone, — недостающее решается флагом, не импровизацией.

## 7. Запреты инструмента

- Не изобретать исторические факты, имена реальных лиц, цитаты, топонимы — только из хроник ✓ или по флагу.
- Не воскрешать выбывших (3.4) ни в какой форме, кроме разрешённых (упоминание, документ, метод).
- Не менять речевые паспорта, психокаркасы и решённые записи 3.6 — предлагать изменения можно только флагом.
- Не сглаживать жёсткие правила ради гладкости сцены (фокализация, стоп-листы, информационный режим): красивая фраза, нарушающая 0.3, — брак, а не находка.

## 8. Роль автора

Автор — единственный источник канонических решений. Инструмент готовит развилки с последствиями, автор решает, журнал фиксирует. Формула из практики серии: «Плану продаётся арка, пишется — том»; канон служит письму, не наоборот.
