# КОНВЕЙЕР УГАР

Программный конвейер производства книжной серии «УГАР» — реализация ТЗ v1.0
(утверждено 31.08.2026, допущения Д-1…Д-12, Р-017).

Система автоматизирует производственный такт главы: сборку окна контекста из
библиотеки канона, генерацию прозы LLM-Писателем (Gemini), двухэшелонную
верификацию (скрипты + Claude), цикл авторских правок с дифф-контролем и
фиксацию принятого в реестры канона — **при сохранении за автором всех
канонических и вкусовых решений**. Весь контур локален; наружу выходят только
вызовы двух API моделей.

## Установка (NFR-1: macOS и Windows, без Docker и серверов)

```bash
pip install -e ".[llm,dev]"   # llm — SDK google-genai и anthropic; dev — pytest
```

Попробовать конвейер за минуту (демо-библиотека, ключи не нужны):

```bash
mkdir демо && cd демо
ugar init --демо              # играбельная рабочая область с демо-каноном
ugar export && ugar compile 1 && ugar status && ugar regress
```

**Реальная библиотека канона уже в репозитории** (`УГАР_Библиотека/`, 30 документов,
`config.yaml` в корне) — сам репозиторий является рабочей областью автора:

```bash
ugar export && ugar compile 5 && ugar status     # прямо из корня репозитория
ugar check "УГАР_Библиотека/Проза/Том1_Глава05.md" --глава 5   # Э1 по принятой главе
```

Парсер написан под фактическую разметку библиотеки (Д-1): нормы читаются из прозы
§5 стилевого регламента, усилители — из решения Р-016 журнала, поглавник тома —
из постраничной сетки реестра информрежима, матрица — широкая, закладки — из §7
реестра, досье — карточки «# Досье 1.3». Что именно читает машина — в
`УГАР_Библиотека/ИНСТРУМЕНТ_Соглашения_разметки.md`.

Настройка отдельной рабочей области (если библиотека живёт в другом месте):

```bash
mkdir мой-проект && cd мой-проект
ugar init                     # config.yaml, папки, .env.example
# положите рядом УГАР_Библиотека/ (git-репозиторий канона)
cp .env.example .env          # впишите GEMINI_API_KEY и ANTHROPIC_API_KEY (Д-9)
ugar doctor                   # диагностика: ключи, SDK, git, выгрузки, регрессия
```

Точные ID моделей пинуются в `config.yaml` (Д-6, Д-11, R-6). Без ключей API
конвейер деградирует в ручной режим: каждый артефакт — человекочитаемый файл,
промпты сохраняются, ответы моделей принимаются файлами (NFR-3).

## Панель (этап 3): весь такт в браузере

Без терминала: двойной клик по `Запустить_панель.bat` (Windows) или
`Запустить_панель.command` (macOS) в корне репозитория. При первом запуске скрипт
сам создаст окружение `.venv` и установит конвейер (нужен только Python 3.11+),
затем откроет панель в браузере; чтобы остановить — закрыть окно. Ключи API —
в файле `.env` рядом (см. выше). Из терминала — то же самое:

```bash
ugar panel        # http://127.0.0.1:8765 — очередь глав, чтение с флагами,
                  # инлайн-правки, кнопки решений по самоволкам, дифф,
                  # приёмка и подпись пакета, дашборд, журнал API
```

React-интерфейс поверх того же пайплайна: сервер слушает только 127.0.0.1,
облака нет (§1.3), FSM и подтверждения автора (Д-8) сохраняются — критерий
этапа 3 «полный такт без терминала» выполняется. Кнопка «Продолжить такт ▶»
выполняет машинные шаги до следующей паузы автора; вывод задач стримится
вживую; вкладка «Окно / ручной режим» позволяет пройти такт вообще без
ключей API — скопировать промпт и вставить ответ модели прямо в браузере
(NFR-3); есть поиск по канону. Собранный интерфейс лежит в данных пакета —
Node автору не нужен; исходники — в `panel/` (Vite + React), пересборка:
`cd panel && npm install && npm run build`.

## Такт главы (сценарий А)

```bash
ugar run 7          # весь такт с паузами на шагах автора (FR-O1), либо по шагам:
ugar export         # MD-библиотека → exports/*.json (FR-X1…X3)
ugar compile 7      # окно контекста по шаблону v1.1 (FR-C1…C6)
ugar write 7        # Писатель → chapters/007/draft_1.md (FR-W1)
ugar verify1 7      # Э1: формальные проверки; брак → авто-повтор ≤2 (FR-V1.*)
ugar verify2 7      # Э2: смысловые проверки Claude → flags.json (FR-V2.*)
ugar review 7       # пакет приёмки: review.md, edits.md, resolutions.json (FR-E1)
ugar apply-edits 7  # Писатель вносит правки точно (FR-W2, FR-E3)
ugar diff-check 7   # дифф-контроль: внесено / не внесено / самоволия (FR-V1.10)
ugar accept 7       # приёмка автором — только из «дифф-контроль: чисто» (FR-E4)
ugar canonize 7     # пакет записей в канон на подпись (FR-K1)
ugar canonize 7 --apply   # правки MD + export + атомарный git-коммит (FR-K2)
```

### Работа с приёмкой и правками

- `ugar review N` дополнительно строит `chapters/N/review.html` — «чтение с
  флагами» в браузере: текст с подсветкой цитат (тултипы с правилом и
  рекомендацией), таблица Э1, карточки Э2, статусы решений по самоволкам и
  дифф черновиков. Файл самодостаточен, сети не требует.
- `ugar status` — все главы: состояние, сводка флагов Э1/Э2 и колонка «Дальше»
  с готовой командой; `ugar status N` — карточка главы (вердикт, флаги,
  нерешённые самоволки, время такта, следующий шаг).
- `ugar resolve N` — самоволки списком; `ugar resolve N F-001 канонизировать
  --реестр 3.1` — решение без ручной правки JSON (FR-V2.5).
- `ugar edits N` — предпросмотр: как парсер понял `edits.md`, с проверкой, что
  каждое «БЫЛО» найдено в черновике дословно, — до вызова Писателя.
- `ugar diff N [k1 k2]` — дифф черновиков (по умолчанию до/после правок).
- `ugar check файл.md [--глава N | --фокал … --год …]` — прогнать проверки Э1
  по любому тексту вне такта (главный инструмент ручного режима, NFR-3).

### Круги истории — каркас драматургии (Р-020)

Круг истории Хармона — несущий каркас драматургии и темпа серии на трёх вложенных
уровнях: круг тома → круги четырёх актов (Р-021: акт = пара шагов круга тома,
таблица актов — в документе 2.1) → круги глав; каждый уровень строится
внутри шага уровня выше. `ugar circles [книга|акты|главы|всё] [--глава N]` и
кнопка «Круги истории» в панели строят восемь шагов («Ты → Потребность → Переход →
Поиск → Обретение → Расплата → Возвращение → Изменение») по материалу канона;
аналитик — модель Anthropic (та же, что у Канониста), без ключа промпты
сохраняются в `круги_истории/промпты/`, ответ вставляется в панели. Черновики —
`круги_истории/*.md|json`; `ugar circles --в-канон` (кнопка «Внести в канон») по
подтверждению автора записывает их в документ канона 2.1
(`21_Круги_истории_Том1.md`) и коммитит. После этого окно каждой главы получает
секцию «Драматургия главы» (шаг тома и акта, на которые приходится глава, и её
собственный круг), а Верификатор-2 проверяет главу по чек-листу 4.4
(флаги типа «драматургия»). Компилятор предупреждает, если каркас главы в канон
ещё не внесён.

### Сервис

`dashboard [--открыть]` (FR-D1) — полностью оффлайн (инлайн-SVG, без CDN),
с блоком состояний глав и временем автора против цели ≤40 минут (критерий
приёмки 1), `find <запрос>` — типизированный поиск по канону (факты, закладки,
правила, брифы, досье, хронология, проза), `snapshot V` — черновик среза тома
(реестр 3.5), `log` — последние API-вызовы с токенами и стоимостью,
`doctor` — диагностика установки, `regress [--llm]` и `add-golden`
(FR-R1…R4), `canon-commit -m "…"` — правка канона автором с валидацией и
проверкой ссылки Р-№ при изменении норм (сценарий Б), `rollback N [--to …]`
(без `--to` — на шаг назад; сценарий Г), `retest` (сценарий В, Д-10),
`backup [--push]` — проверка бэкапа и отправка во все remotes (NFR-6).
Автодополнение shell: `ugar --install-completion`. Если команда `ugar` не в PATH — `python -m ugar …`. Для оценки стоимости в
`logs/api.jsonl` задайте цены моделей (`price_in_per_1m`/`price_out_per_1m`)
в `config.yaml` (§6.3).

## Ключевые гарантии

- **Пороги — только из канона.** Все нормы Э1 берутся из `exports/norms.json`,
  сгенерированного из `02 §5`; в коде констант нет (критерий приёмки 6).
- **Запись в канон — только через подпись.** Единая точка записи файлов
  (`ugar/guard.py`) блокирует любой путь записи в `УГАР_Библиотека/`, кроме
  `canonize --apply` после подтверждения автора (FR-K3, критерий 3).
- **Детерминизм.** Одинаковые вход и выгрузки → байт-в-байт одинаковое окно
  (FR-C4); `export` идемпотентен, хэши выгрузок логируются (FR-X3).
- **Полная история.** Все артефакты такта хранятся в `chapters/N/` и не
  удаляются (NFR-4); состояние главы — FSM в `status.yaml` (§5.4, Д-5).

## Структура репозитория

- `ugar/` — пакет конвейера (CLI `ugar`, модули по реестру 4.2 ТЗ).
- `ugar/templates/` — промпт-шаблоны (окно v1.1, режим правок, Верификатор-2,
  Канонист); переопределяются копией в `templates/` рабочей области (§6.2).
- `ugar/data/демо/` — демо-библиотека по соглашениям разметки
  (`ИНСТРУМЕНТ_Соглашения_разметки.md`, Д-1) и стартовый регрессионный корпус
  «красных» тестов (FR-R4); разворачивается командой `ugar init --демо`
  и служит фикстурой тестов.
- `tests/` — pytest-набор по разделу 10 ТЗ: калибровка счётчиков (10.1),
  флаговые тесты (10.2), FSM (10.5), сквозной такт с git-коммитом, защита канона.
- `panel/` — исходники React-панели (Vite, TypeScript); сборка коммитится в
  `ugar/data/панель/` и раздаётся сервером `ugar/server.py` (`ugar panel`).

```bash
python -m pytest tests/    # 125 тестов
```

## Соответствие этапности ТЗ

- **Этап 1 «Скрипты»** — готов: exporter с валидацией, compiler, verifier-1
  полностью, адаптеры API с журналом `logs/api.jsonl`, команды
  `export/compile/write/verify1/status`.
- **Этап 2 «Пайплайн»** — готов: FSM и `run`, verify2, цикл правок с
  дифф-контролем, канонист, регрессия, дашборд, `rollback`.
- **Этап 3 «Панель»** — готов: `ugar panel` — React-интерфейс поверх
  пайплайна (очередь, чтение с флагами, инлайн-правки, кнопки решений, дифф,
  дашборд, журнал); полный такт без терминала. Плюс автономный `review.html`
  для чтения с флагами вовсе без сервера.
