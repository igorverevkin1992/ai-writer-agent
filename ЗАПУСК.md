# ЗАПУСК КОНВЕЙЕРА — пошаговая инструкция (Windows, PowerShell)

Для macOS команды те же, кроме отмеченных; вместо `.bat` — `Запустить_панель.command`.

## Шаг 0. Что должно быть установлено (один раз)

1. **Python 3.11 или новее** — https://www.python.org/downloads/ . При установке
   поставьте галочку **«Add python.exe to PATH»**.
2. **Git** — https://git-scm.com/download/win (все настройки по умолчанию).

Проверка в PowerShell (обе команды должны напечатать версию):

```powershell
py --version
git --version
```

## Шаг 1. Получить актуальный код

```powershell
cd <папка-репозитория>          # например: cd "D:\проекты\ai-writer-agent"
git pull                        # рабочая ветка — та, в которой ведётся разработка (по умолчанию main)
```

Если папки ещё нет:

```powershell
git clone https://github.com/igorverevkin1992/ai-writer-agent
cd ai-writer-agent
```

## Шаг 2. Ключи API (один раз)

В корне папки создайте файл `.env` (без имени, только расширение):

```powershell
notepad .env
```

Содержимое — две строки, без кавычек и пробелов вокруг `=`:

```
GEMINI_API_KEY=ваш_ключ_Gemini
ANTHROPIC_API_KEY=ваш_ключ_Anthropic
```

Сохраните. Файл в `.gitignore`, в репозиторий не попадёт. Без ключей всё
работает в ручном режиме (промпты сохраняются в файлы, ответы моделей
вставляются в панели).

## Шаг 3. Запуск панели

### Вариант А — двойной клик (рекомендуется)

Откройте папку в Проводнике и дважды щёлкните `Запустить_панель.bat`.

- Первый запуск: скрипт создаёт окружение `.venv` и ставит конвейер (1–3 мин).
- Затем открывается браузер с панелью: http://127.0.0.1:8765 .
- Чёрное окно — это сервер. Закрыть окно = остановить панель.

### Вариант Б — из PowerShell

```powershell
cd <папка-репозитория>
py -m venv .venv                       # один раз
.\.venv\Scripts\Activate.ps1           # каждый новый сеанс PowerShell
python -m pip install -e ".[llm,dev]"  # один раз (и после git pull)
chcp 65001                             # русские буквы в терминале
ugar doctor                            # диагностика: ключи, SDK, git, выгрузки
ugar panel                             # панель в браузере
```

Если PowerShell отказывается выполнять `Activate.ps1`, один раз:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## Шаг 4. Первый сеанс в панели

1. **Экспорт канона** (кнопка слева) — библиотека `УГАР_Библиотека/` → `exports/`.
   Делается автоматически перед каждым шагом, кнопка нужна после ручной правки канона.
2. **Круги истории** (кнопка слева) → **«Построить все круги»**: круг тома, четыре
   акта, 46 глав — 51 вызов модели Anthropic. Дождитесь окончания (лог справа).
3. Просмотрите круги (клик по карточке раскрывает 8 шагов и «слабое место»).
   Не нравится — **«Пересчитать всё»** или пересчёт одного уровня (Книга / Акты / Главы).
4. **«Внести в канон»** — круги записываются в `УГАР_Библиотека/21_Круги_истории_Том1.md`
   и коммитятся. С этого момента окно каждой главы содержит секцию «Драматургия».
5. Границы актов при необходимости правятся в таблице «Акты тома» того же документа,
   затем **Экспорт канона**.

## Шаг 5. Такт главы в панели

1. В очереди слева выберите главу (например, «Глава 1 · не начата»).
2. **«Продолжить такт ▶»** — конвейер выполняет машинные шаги подряд:
   сборка окна → Писатель (Gemini) → проверки Э1 → проверки Э2 (Claude) → пакет приёмки,
   и останавливается на паузе автора.
3. **Приёмка** (вкладка «Чтение с флагами»): текст с подсветкой флагов;
   вкладка «Правки» — впишите правки в формате БЫЛО/СТАЛО; по каждой самоволке
   нажмите «Вычеркнуть» или «Канонизировать →».
4. **«Продолжить такт ▶»** — Писатель вносит правки, дифф-контроль сверяет
   внесённое.
5. Если «дифф-контроль: чисто» — **«Принять главу»**. Затем **«Пакет в канон»**:
   просмотрите/поправьте пакет записей и **«Применить пакет + коммит»** — текст главы
   и записи реестров уходят в библиотеку и коммитятся.
6. Глава становится «зафиксировано». Дальше следующая глава.

Вкладка «Окно / ручной режим» позволяет пройти всё без ключей: скопировать промпт,
вставить ответ модели.

## Шаг 5а. Правка канона с проверкой противоречий

1. Кнопка **«Канон»** слева. Список документов библиотеки, редактор и находки линтера.
2. Правьте документ в редакторе или в своём редакторе на диске: сервер замечает изменение
   и перепроверяет канон сам. Ошибки (красные) — прямые противоречия: хронология, ссылки на
   несуществующие главы, недопустимый фокал; предупреждения — тайны в брифах/прозе, расхождения
   реестра тайн и матрицы, возраст; заметки — что стоит уточнить.
3. **«Сохранить (Ctrl+S)»** → подтверждение → файл в библиотеке перезаписан, выгрузки и проверка
   обновлены. **«Применить исправление»** — для механических правок. **«Проверить моделью»** —
   смысловые противоречия (вызовы Anthropic). **«Закоммитить канон»** — сообщение и коммит.

## Шаг 6. То же самое из терминала (по шагам)

```powershell
ugar status            # все главы и что делать дальше
ugar run 1             # весь такт главы 1 с паузами на шагах автора
# либо по шагам:
ugar compile 1         # окно контекста → chapters/001/window.md
ugar write 1           # Писатель → draft_1.md   (--manual без ключа; --варианты 2 — A/B, --выбрать alt1)
ugar verify1 1         # Э1 (скрипты)
ugar verify2 1         # Э2 (Claude)            (--manual без ключа; --вкус — советы по вкусу;
                       #                          --повторно — второй Э2 после правок, совещательно)
ugar review 1          # review.md / review.html, edits.md, resolutions.json
ugar resolve 1         # решения по самоволкам
ugar apply-edits 1     # дословные БЫЛО/СТАЛО вносит код без модели; Писатель — только для «УКАЗАНИЕ»
ugar diff-check 1      # дифф-контроль
ugar accept 1          # приёмка
ugar canonize 1        # пакет на подпись
ugar canonize 1 --apply
```

Круги истории из терминала:

```powershell
ugar circles всё       # или: книга | акты | главы [--глава N]; --заново пересчёт
ugar circles --в-канон # внести черновики в документ 2.1 и закоммитить
```

Служебное:

```powershell
ugar --version                    # версия конвейера
ugar doctor                       # диагностика: ключи, SDK, пины моделей против API, git, архив, регрессия
ugar canon-commit -m "текст"      # закоммитить ручную правку библиотеки (с итогом линтера)
ugar lint [--llm] [--watch]       # противоречия канона; --watch — следить за папкой
ugar backup                       # состояние копий библиотеки и возраст архива рабочей области
ugar backup --push                # библиотека — во все remotes
ugar backup --архив               # zip рабочей области (см. шаг 8)
ugar rollback 1                   # откат главы на шаг назад
ugar dashboard --открыть          # дашборд
ugar find "Штерн"                 # поиск по канону
python -m pytest tests/ -q        # тесты (365)
```

## Шаг 7. Обновление кода

```powershell
cd <папка-репозитория>
git pull
.\.venv\Scripts\python.exe -m pip install -e ".[llm,dev]"
ugar doctor                       # SDK, пины моделей, регрессия
```

**Версии библиотек.** `pyproject.toml` держит SDK моделей в пределах мажорной версии
(`google-genai<3`, `anthropic<2`) — смена мажора меняет HTTP-стек и типы, её нельзя получать
случайно. `requirements.lock` — точные версии, на которых тесты были зелёными. Если после
обновления что-то сломалось, вернитесь ровно к проверенному набору:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install -e . --no-deps
```

Осознанное обновление SDK (например, вышел новый мажор): поднять границу в `pyproject.toml`,
`pip install -e ".[llm,dev]" --upgrade`, `python -m pytest tests/ -q`, `ugar doctor` (пины
моделей на месте), `ugar regress` (FR-R3) — и только потом обновить `requirements.lock`
(`pip freeze` по перечисленным в нём пакетам) одним коммитом с текстом «зависимости: …».
Смена самой модели — по-прежнему только через `ugar retest` и запись в журнал 3.6.

## Шаг 8. Сохранность: библиотека, копии, архив

Что где лежит и что чем защищено:

| Что | Где | Защита |
|---|---|---|
| Канон и принятая проза | `УГАР_Библиотека/` — git-репозиторий | коммит на каждую приёмку (`[глава N]`) и тег `глава-N`; ≥ 2 удалённых копий (NFR-6) |
| Черновики, правки автора, флаги, журнал API, круги, снапшоты, корпус | `chapters/ logs/ круги_истории/ snapshots/ regression/ config.yaml` — вне git | zip-архив `ugar backup --архив` (и автоматически после каждой приёмки, если задан `backup_dir`) |

### 8.1. Библиотека — отдельный репозиторий

`ugar doctor` называет раскладку словами:

- **«библиотека — корень собственного репозитория»** — норма: канон живёт своей историей,
  обновление кода конвейера (`git pull`) её не касается.
- **«библиотека внутри репозитория кода»** — так сейчас в этом репозитории. Работает, но
  `git pull` кода принесёт конфликты с каноническими коммитами автора, а откат кода откатит и
  канон. Переезд — одной командой:

```powershell
ugar library-split --показать     # план: куда, что запишется в config.yaml и .gitignore
ugar library-split                # перенос в ..\УГАР_Библиотека, git init, первый коммит, library_dir
ugar library-split --с-историей   # то же, но с историей папки (git subtree split): SHA приёмок
                                  # в status.yaml пересчитываются, откат старых глав остаётся возможен
```

  Без `--с-историей` история канона до переезда остаётся в репозитории кода, новая начинается
  с первого коммита; уже зафиксированные главы после этого нельзя откатить git-revert'ом
  (команда об этом предупредит и снимет устаревшие SHA из `status.yaml`). После переезда
  закоммитьте в репозитории кода удаление папки (команда печатает что именно).
- **«библиотека не под git»** — приёмка глав невозможна (FR-K2); `git init` в папке или
  `ugar library-split`.

Куда именно переезжать (соседняя папка по умолчанию, другой диск — `--в <путь>`) и где
хранить копии — решение автора (аудит 2, Р-№ 6).

### 8.2. Вторая копия без облака (§1.3 ТЗ)

ТЗ §1.3: «никакого облака», наружу — только вызовы API моделей. Репозиторий на GitHub — это
облако; держать там канон и прозу можно только **сознательным решением автора** (приватный
репозиторий как одна из копий). Вариант без облака — папка на внешнем диске или сетевом
хранилище как bare-репозиторий git:

```powershell
ugar backup --добавить-remote диск "E:\УГАР_Библиотека.git"   # папки нет — создастся (git init --bare)
ugar backup --добавить-remote github https://github.com/<автор>/<библиотека>.git   # если решено
ugar backup --push                                           # во все места сразу
ugar doctor                                                  # «удалённых копий: 2 (нужно ≥2)»
```

Второй внешний диск — ещё один `--добавить-remote`. Восстановление с диска: `git clone E:\УГАР_Библиотека.git УГАР_Библиотека`.

### 8.3. Архив рабочей области

```powershell
ugar backup --архив                 # zip в backup_dir из config.yaml, иначе ..\УГАР_бэкап
ugar backup --архив "E:\УГАР_бэкап" # в указанную папку
```

Имя архива — `УГАР_рабочая_область_<дата_время>.zip`; хранится `backup_keep` последних
(по умолчанию 10). Чтобы архив делался сам после каждой приёмки главы, раскомментируйте в
`config.yaml`:

```yaml
backup_dir: "../УГАР_бэкап"
backup_keep: 10
```

`ugar doctor` и `ugar backup` показывают возраст последнего архива. Кнопка в панели появится
после слияния с изменениями сервера (пока — только команда).

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `ugar` не распознано | Активируйте окружение `.\.venv\Scripts\Activate.ps1` или вызывайте `.\.venv\Scripts\python.exe -m ugar panel` |
| Порт занят | `ugar panel --port 8766` |
| Кракозябры в терминале | `chcp 65001` |
| «Не найден GEMINI_API_KEY / ANTHROPIC_API_KEY» | Проверьте `.env` в корне папки; либо работайте в ручном режиме |
| Панель не открылась сама | Откройте в браузере http://127.0.0.1:8765 |
| «в библиотеке незакоммиченные изменения» | `ugar canon-commit -m "правка канона"` и повторите |
| `doctor`: «модель … не найдена в API» | модель снята или ID неверен — новый пин через `ugar retest` (Д-11), затем поправьте `config.yaml` |
| После `pip install --upgrade` тесты красные | вернитесь к `requirements.lock` (шаг 7) |
| Сомнения в установке | `ugar doctor` |
